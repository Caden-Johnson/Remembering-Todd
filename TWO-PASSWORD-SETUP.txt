TWO-PASSWORD ADMIN SETUP

WHAT THIS DOES
- Family password: view-only
- Owner password: view + permanently delete submissions/photos
- Every refresh/reopen requires a password again
- Multiple people can view at the same time
- Passwords are handled by Supabase Auth, not stored in GitHub

FILES TO REPLACE/UPLOAD IN GITHUB ROOT
- admin.html
- admin.css
- admin.js
- admin-config.js

You may also upload:
- admin-two-role-setup.sql

SUPABASE

Your existing family/view account should remain:
family-admin@rememberingtodd.local

1. Go to Authentication -> Users.
2. Create a NEW owner user:
   owner-admin@rememberingtodd.local
3. Choose a different password only you know.
4. Copy the new owner's UUID.

5. Go to SQL Editor.
6. Run all of admin-two-role-setup.sql.

7. Then run this with your new owner UUID:

insert into public.memorial_admins (user_id, role)
values ('PASTE-OWNER-UUID-HERE', 'owner')
on conflict (user_id) do update set role = 'owner';

8. Your existing family account should be view-only. To make absolutely sure, run:

update public.memorial_admins
set role = 'viewer'
where user_id = 'PASTE-FAMILY-USER-UUID-HERE';

If you no longer know the old family UUID, it is visible under Authentication -> Users.

LOGIN BEHAVIOR
The admin page contains only ONE password field.
- Entering the family password opens view-only mode.
- Entering the owner password opens owner mode.
- Reloading or reopening the page locks it again.

OWNER DELETE
Owner mode shows a "Delete submission" button.
It asks for confirmation, removes attached photos from Storage, and then removes the database row.

There is deliberately NO edit/update function yet.
